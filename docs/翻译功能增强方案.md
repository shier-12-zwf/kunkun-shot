> 目标：把 GitHub 仓库 `kunkun-translator`（Swift 原生 macOS 划词翻译 App）的能力，
> 移植进本截图工具（Electron）。因两边语言不同（Swift vs JS），**不是复制代码，而是照逻辑重写**。
>
> 本次确认范围（困困 2026-07-01 拍板）：
> - **A. 多 provider + 在线模型列表**
> - **B. 全局划词翻译（纯 Electron 版：快捷键 + 剪贴板兜底）**
> - 生词本/朗读/学习总结/苹果离线翻译 → 本次不做

## 二、A 部分：多 provider + 在线模型列表

### A1. 数据模型：把 provider 从「2 个写死」升级为「provider 表 + 自定义」

**改 `config-schema.js`**，新增统一的 provider 目录（不破坏现有 deepseek/minimax 字段，向后兼容）：

```js
// 新增：可扩展的 provider 目录（OpenAI 兼容协议）
providers: {
  // 现有两个保留，另加这些
  deepseek:    { baseUrl: 'https://api.deepseek.com/v1',                       defaultModel: 'deepseek-v4-flash' },
  minimax:     { baseUrl: 'https://api.minimaxi.com/v1',                       defaultModel: 'MiniMax-M3' },
  siliconflow: { baseUrl: 'https://api.siliconflow.cn/v1',                     defaultModel: 'deepseek-ai/DeepSeek-V3', supportsModelList: true },
  qwen:        { baseUrl: 'https://dashscope.aliyuncs.com/compatible-mode/v1', defaultModel: 'qwen-turbo' },
  kimi:        { baseUrl: 'https://api.moonshot.cn/v1',                        defaultModel: 'moonshot-v1-8k' },
  custom:      { baseUrl: '',                                                  defaultModel: '', supportsModelList: true },
},
// 每个 provider 的 apiKey 单独存（不同厂商 key 不通用）
providerKeys: { deepseek: '', minimax: '', siliconflow: '', qwen: '', kimi: '', custom: '' },
```

> provider→baseURL→默认模型 对照表（来自 Swift `SettingsStore.swift`，2026-07 已核实）：
> | provider | baseURL | 默认模型 |
> |---|---|---|
> | 硅基流动 | https://api.siliconflow.cn/v1 | deepseek-ai/DeepSeek-V3 |
> | DeepSeek | https://api.deepseek.com/v1 | deepseek-v4-flash |
> | 通义千问 | https://dashscope.aliyuncs.com/compatible-mode/v1 | qwen-turbo |
> | Kimi | https://api.moonshot.cn/v1 | moonshot-v1-8k |
> | 自定义 | （用户填） | （用户填） |

### A2. 在线拉模型列表（`GET {baseUrl}/models`）

在 `deepseek.js` 里新增（对应 Swift `ModelCatalog.fetchModels`）：

```js
async function fetchModels({ baseUrl, apiKey }) {
  const url = `${String(baseUrl).replace(/\/$/, '')}/models?type=text`;
  const res = await fetch(url, { headers: { Authorization: `Bearer ${apiKey}`, Accept: 'application/json' } });
  if (!res.ok) throw new Error(`${res.status}: ${(await res.text()).slice(0,300)}`);
  const j = await res.json();
  return (j.data || []).map(m => m.id).filter(Boolean).sort((a,b)=>a.toLowerCase()<b.toLowerCase()?-1:1);
}
```
- 新增 IPC 通道 `AI_FETCH_MODELS`，设置页点「刷新模型列表」时调用。
- 硅基流动/自定义 才显示「刷新」按钮（`supportsModelList`）。

### A3. 让 `aiProvider()` 认识新 provider

`main.js:105` 的 `aiProvider()` 目前只识别 deepseek/minimax。改为：
- 读 `config.ai.provider`（现有），若值命中 `providers` 表则用表里的 baseUrl/model + `providerKeys[name]`。
- 保留现有 `auto` 智能分流逻辑（纯文本 DeepSeek / 看图 MiniMax）不变，只是把「文本 provider」从写死 deepseek 改为「当前选中的文本 provider」。

### A4. 健壮 JSON 解析（从 Swift `LLMClient` 搬）

现有 `TRANSLATE_TEXT`（`main.js:494-513`）已做了编号 JSON + 提取 `[...]`，但对「中文引号/尾逗号/全角标点」不够健壮。移植 Swift 的 `repairJSONNoise`：
- 中文/智能引号 `""„「」＂` → ASCII `"`
- 全角 `：，` → `:,`
- 字符串内裸换行/制表 → `\n \t`
- 去尾逗号 `,}` `,]`
封装成 `deepseek.js` 里的 `repairJsonNoise(str)`，`TRANSLATE_TEXT` 解析前先过一遍。

### A5. 设置页 UI

`src/renderer/main/pages/settings.js` 增加：
- provider 下拉（6 项）
- baseURL / apiKey / model 输入（切 provider 自动填默认值）
- 「刷新模型列表」按钮（仅 supportsModelList 的 provider）+ model 下拉

## 三、B 部分：全局划词翻译（纯 Electron）

### B1. 数据流

```
全局快捷键（默认 Cmd+Shift+T，可配）
  → 记录当前剪贴板内容（备份）
  → 模拟 Cmd+C（robotjs 或 macOS `osascript`/AppleScript keystroke）
  → 读剪贴板文字 selection
  → 还原剪贴板（用备份覆盖回去）
  → 在鼠标位置附近创建「划词翻译卡片」透明窗口
  → 调 TRANSLATE_TEXT（复用现有翻译链路，target 取 config.translate.target）
  → 卡片流式/一次性显示译文
```

### B2. 模拟 Cmd+C 的实现选择

- **优先**：`osascript -e 'tell application "System Events" to keystroke "c" using command down'`（无需装原生依赖，但需「辅助功能」权限）。
- 备选：`robotjs`（需编译原生模块，打包麻烦）。
- **推荐 osascript**，零依赖，配合权限引导。

### B3. 权限

macOS 上「模拟按键」需要**辅助功能权限**。用 `systemPreferences.isTrustedAccessibilityClient(true)` 检测并弹系统引导（项目已在用 systemPreferences，模式一致）。

### B4. 划词卡片窗口

新建 `src/renderer/translate-popup/`（HTML/CSS/JS），窗口用 `windows.js` 里现成的透明 `alwaysOnTop` `skipTaskbar` 模式（照抄 `createPin`/`togglePopover`）。窗口出现在 `screen.getCursorScreenPoint()` 附近，做好屏幕边界收敛（别超出屏幕）。

卡片内容：原文（可折叠）+ 译文 + 关闭按钮 +（可选）复制译文。

### B5. 剪贴板还原的坑（务必处理）

- 备份要**同时处理文本和图片**（现有 `clipboard.readImage/readText` 都有）。用户剪贴板里若是图片，还原时要写回图片。
- Cmd+C 后要**等一小段**（~150ms）再读剪贴板（系统写入有延迟），Swift 版也是这么等的。
- 若 selection 为空（用户没选中文字）→ 静默不弹卡片，别报错打扰。

### B6. 新增 IPC / 通道

```js
// channels.js
GLOBAL_TRANSLATE: 'translate:global',          // 主进程触发划词
TRANSLATE_POPUP_DATA: 'translate:popup-data',  // main->popup 送原文/译文
```
