# PixPin 竞品对比与改进报告

> 截止日期：2026-09-01
>
> 对比对象：**PixPin**（官方标准名称，含义为 “Pixel Pin”）。用户口语中的 **PinPix** 在本报告中视为同一产品的别名或误写，不另指另一款软件。
> 我方版本：困困截图工具 `v0.2.1`（本轮计划发布的源码版本），macOS 早期预览版。

## 1. 结论先行

困困截图工具已经覆盖 PixPin 最重要的主流程：区域/窗口/全屏/延时截图、常用标注、图片/文字/颜色/文件贴图、本地 OCR、二维码、长截图、录屏、历史库和多格式导出。它不是“只有界面”的原型；多数主链路在代码和自动测试中都有实际实现。

但当前还不能把它表述成“已经全面追平 PixPin”。主要原因不是功能数量，而是成熟度和边界不同：

1. PixPin 是持续迭代的 Windows/macOS 成熟产品；我方仍是 macOS 早期预览版，发布清单中的真机项目尚未形成完整验收证据。
2. 我方在精确选区、贴图分组/变换、长截图后编辑、录屏增强、文件命名与自动保存规则等细节上仍有差距。
3. PixPin 测试版正在试验多区域/自由形状截图、动态贴图、录屏崩溃恢复等功能，这些不应被当作正式版基线，也不适合本轮无差别追赶。
4. 我方有自己的差异化方向：开源、离线 OCR 失败关闭、AI 数据流与密钥边界更透明、独立历史库、截图原位翻译、AI 问答/总结/润色，以及受控启动参数。应继续强化这些价值，而不是做成 PixPin 的逐像素复刻。

本轮最优先事项仍是把现有能力做成**可重复测试、可稳定打包、可在真实 Mac 安装更新并通过验收**的产品；在这条门槛通过前，不建议把跨平台或测试版高级功能提到 P0。

## 2. 口径与证据等级

本报告的 PixPin 信息只采用其官方站点、官方文档、官方更新日志、官方政策页。没有把媒体测评、软件下载站文案或用户转述当作产品事实。

我方状态依据当前仓库的 [README](../README.md)、[PRD](PRD.md)、[发布检查清单](RELEASE_CHECKLIST.md)、源代码和自动化测试判断。状态含义如下：

| 状态 | 含义 |
| --- | --- |
| 已具备 | 当前代码存在完整基础链路，并有文档或自动测试支撑；不自动等于真机已验收 |
| 部分具备 | 主链路已存在，但范围、交互深度、平台或可靠性证据少于 PixPin |
| 尚缺 | 在当前仓库没有找到对应实现或产品入口 |
| 不应本轮硬追 | 成本高、偏离当前 macOS 定位，或只属于 PixPin 测试版，适合先验证需求 |
| 需实机确认 | 静态代码和自动测试无法证明真实权限、显示器、拖拽、编码、系统兼容或交互体验 |

特别注意：仓库的发布检查清单明确规定，自动测试不能替代 macOS 屏幕录制权限、多显示器、全局快捷键、OCR、录屏音频、贴图拖拽、格式兼容和 Apple 分发链路的真机验收。当前不能把未勾选项目写成“已发布验证”。

截至 2026-09-01，官方可核验的版本边界如下：

| 通道 | 截止日可核验版本 | 本报告如何使用 |
| --- | --- | --- |

| 测试版 | [3.5.2.2，2026-08-18](https://pixpin.cn/docs/change-log/3.5.2.2) | 只用于观察方向，不作为“我方必须马上补齐”的正式缺口 |
| 测试版风险 | 官方[测试版说明](https://pixpin.cn/docs/change-log/instructions)提示测试版本用于提前体验，稳定性不能等同正式版 | 所有测试版能力均标注“测试版”，不能混入正式版宣传 |

测试版近期可观察到的方向包括：

- 3.5.2.2：自由形状/多边形/多线段、多窗口或多区域截图，表格单元格编辑，录屏异常恢复，长截图穿透与快捷键，以及 OCR 高亮/自动复制等。证据见[官方 3.5.2.2 日志](https://pixpin.cn/docs/change-log/3.5.2.2)。
- 3.5.0.8：动态 GIF/WebP 贴图播放、三分线、贴图对齐、macOS 桌面范围和 MP4 GPU 导出等。证据见[官方 3.5.0.8 日志](https://pixpin.cn/docs/change-log/3.5.0.8)。

这些条目说明 PixPin 的发展方向，但不能据此声称所有用户、所有平台或正式版已经拥有同样表现。尤其是崩溃恢复、GPU 编码、自由形状截图等高复杂度能力，应在需求和实机价值被证实后再排期。

#### 自动滚动的官方文档不一致

PixPin 的[2.3.8.0 官方日志](https://pixpin.cn/docs/official-log/2.3.8.0)明确记录过长截图“自动滚动”能力；但当前[长截图指南](https://pixpin.cn/docs/capture/long-capture)只描述用户转动滚轮或拖动滚动条，未说明自动滚动的入口、支持平台和限制。

因此能确认的事实只有两点：

1. PixPin 曾在正式更新日志中发布过自动滚动。
2. 当前官方主指南没有把它作为通用操作流程说明。

不能仅凭第二点推断功能已经删除，也不能仅凭历史日志推断 3.4.3.2 在 Windows/macOS、浏览器/原生应用、纵向/横向场景仍然可靠可用。需要分别安装正式版 3.4.3.2 和测试版 3.5.2.2 实测入口、支持范围、速度、终止方式和失败表现。

我方的“自动抓帧并拼接”不等于“自动滚动目标页面”，文档必须继续区分这两个概念。在竞品实测前，不建议为了一个尚未确认的表面差距引入系统级滚轮事件、Accessibility 操作或浏览器脚本注入。

## 5. 我方已经形成的差异化

这些不是“PixPin 没有”的绝对结论，而是当前官方材料与我方产品设计呈现出的不同重点：

1. **开源与可审计的数据边界**：本地 OCR 缺模型时明确失败，不从 CDN 静默下载；密钥无法加密时拒绝落盘；AI 的图像/文字路由在文档中公开。
2. **截图原位翻译**：按 Vision OCR 行框覆盖译文，并把译文合成到复制/保存结果；这比只返回一段翻译文本更贴近日常阅读场景。
3. **更通用的 AI 工作台**：除 OCR 延伸能力外，还包括问图、总结、润色、流式回复和多个兼容服务端点。
4. **独立历史资料库**：图片、长截图和录屏可统一按日期/类型查看、复制、导出和批量清理，不只依赖截图过程中的“上一张”。
5. **受控启动参数**：允许外部流程直接唤起区域/全屏/窗口/OCR/长截图/录屏，同时保持 GUI、权限和严格参数校验边界。

这些方向值得继续做深，但仍须用真实安装包、真实数据流和真实场景验证后再对外宣传。
