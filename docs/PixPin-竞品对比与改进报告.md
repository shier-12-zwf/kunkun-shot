# PixPin 竞品对比与改进报告

> 截止日期：2026-09-03
>
> 对比对象：**PixPin**（官方标准名称，含义为 “Pixel Pin”）。用户口语中的 **PinPix** 在本报告中视为同一产品的别名或误写，不另指另一款软件。
> 我方版本：困困截图工具 `v0.3.1`，macOS 早期预览版。

## 1. 结论先行

困困截图工具已经覆盖 PixPin 最重要的主流程：区域/窗口/全屏/延时截图、精确选区、常用及高级标注、图片/文字/颜色/文件/本地 LaTeX 贴图、多语本地 OCR、二维码与多种条码、可后编辑长截图、增强录屏、历史库和多格式导出。它不是“只有界面”的原型；这些主链路均能在当前代码和自动测试中找到实现证据。

但当前还不能把它表述成“已经全面追平 PixPin”。主要原因不是功能数量，而是成熟度和边界不同：

1. PixPin 是持续迭代的 Windows/macOS 成熟产品；我方仍是 macOS 早期预览版，发布清单中的真机项目尚未形成完整验收证据。
2. `v0.3.0` 已补齐精确宽高/比例、有限贴图分组与图像变换、长截图分段重拼、录屏点击/快捷键/摄像头/成片画笔、文件名模板和历史图片多页 PDF；剩余差距主要在能力深度、复杂场景稳定性和真机证据，而非这些入口是否存在。
3. PixPin 测试版正在试验多区域/自由形状截图、动态贴图、录屏崩溃恢复、更多快捷动作和保存变量等功能，这些不应被当作正式版基线，也不适合本轮无差别追赶。
4. 我方有自己的差异化方向：开源、离线 OCR 失败关闭、AI 数据流与密钥边界更透明、独立历史库、截图原位翻译、AI 问答/总结/润色，以及受控启动参数。应继续强化这些价值，而不是做成 PixPin 的逐像素复刻。

`v0.3.1` 候选源码已在本机重新通过 461 项源码回归、源码态 Electron 正常/故障注入冒烟和非标准视口工具栏自动化，并修正全新 CI runner 上真实离线 OCR 冷启动的测试等待预算；打包态与本机安装的历史证据仍属于 `v0.3.0`，`v0.3.1` 的精确远端与安装证据以[发布检查清单](RELEASE_CHECKLIST.md)和对应 Release 为准。真实屏幕权限、多显示器/Retina、复杂长截图样本、录屏音视频与辅助权限、真实大图贴图等场景仍须人工验收。本文不据此声称 Developer ID 公证、公开二进制正式发布或全面追平 PixPin。

## 2. 口径与证据等级

本报告的 PixPin 信息只采用其官方站点、官方文档、官方更新日志、官方政策页。没有把媒体测评、软件下载站文案或用户转述当作产品事实。

我方状态依据当前仓库的 [README](../README.md)、[PRD](PRD.md)、[发布检查清单](RELEASE_CHECKLIST.md)、源代码和自动化测试判断。状态含义如下：

| 状态 | 含义 |
| --- | --- |
| 已具备 | 当前代码存在完整基础链路，并有文档或自动测试支撑；不自动等于真机已验收 |
| 部分具备 | 主链路已存在，但范围、交互深度、平台或可靠性证据少于 PixPin |
| 尚缺 | 在当前仓库没有找到对应实现或产品入口 |
| 不应本轮硬追 | 成本高、偏离当前 macOS 定位，或只属于 PixPin 测试版，适合先验证需求 |
| 需实机确认 | 静态代码和自动测试无法证明真实权限、显示器、拖拽、编码、系统兼容或交互体验 |

特别注意：仓库的发布检查清单明确规定，自动测试不能替代 macOS 屏幕录制权限、多显示器、全局快捷键、OCR、录屏音频、贴图拖拽、格式兼容和 Apple 分发链路的真机验收。当前不能把未勾选项目写成“已发布验证”。

测试版近期可观察到的方向包括：

- 3.5.4.1：增加公式复制后关闭、录制暂停快捷动作、箭头序号、保存路径变量与全局序号计数等能力，并修复图片到图片翻译和多屏截图提示。证据见[官方 3.5.4.1 日志](https://pixpin.cn/docs/change-log/3.5.4.1)。

这些条目说明 PixPin 的发展方向，但不能据此声称所有用户、所有平台或正式版已经拥有同样表现。尤其是崩溃恢复、GPU 编码、自由形状截图等高复杂度能力，应在需求和实机价值被证实后再排期。

#### 自动滚动的官方文档不一致

PixPin 的[2.3.8.0 官方日志](https://pixpin.cn/docs/official-log/2.3.8.0)明确记录过长截图“自动滚动”能力；但当前[长截图指南](https://pixpin.cn/docs/capture/long-capture)只描述用户转动滚轮或拖动滚动条，未说明自动滚动的入口、支持平台和限制。

因此能确认的事实只有两点：

1. PixPin 曾在正式更新日志中发布过自动滚动。
2. 当前官方主指南没有把它作为通用操作流程说明。

不能仅凭第二点推断功能已经删除，也不能仅凭历史日志推断 3.4.3.2 在 Windows/macOS、浏览器/原生应用、纵向/横向场景仍然可靠可用。需要分别安装正式版 3.4.3.2 和测试版 3.5.4.1 实测入口、支持范围、速度、终止方式和失败表现。

我方的“自动抓帧并拼接”不等于“自动滚动目标页面”，文档必须继续区分这两个概念。在竞品实测前，不建议为了一个尚未确认的表面差距引入系统级滚轮事件、Accessibility 操作或浏览器脚本注入。

## 5. 我方已经形成的差异化

这些不是“PixPin 没有”的绝对结论，而是当前官方材料与我方产品设计呈现出的不同重点：

1. **开源与可审计的数据边界**：本地 OCR 缺模型时明确失败，不从 CDN 静默下载；密钥无法加密时拒绝落盘；AI 的图像/文字路由在文档中公开。
2. **截图原位翻译**：按 Vision OCR 行框覆盖译文，并把译文合成到复制/保存结果；这比只返回一段翻译文本更贴近日常阅读场景。
3. **更通用的 AI 工作台**：除 OCR 延伸能力外，还包括问图、总结、润色、流式回复和多个兼容服务端点。
4. **独立历史资料库**：图片、长截图和录屏可统一按日期/类型查看、复制、导出和批量清理，不只依赖截图过程中的“上一张”。
5. **受控启动参数**：允许外部流程直接唤起区域/全屏/窗口/OCR/长截图/录屏，同时保持 GUI、权限和严格参数校验边界。

这些方向值得继续做深，但仍须用真实安装包、真实数据流和真实场景验证后再对外宣传。

## 7. 剩余路线图

### P0：发布前必须完成

1. **每个发布提交都重跑完整证据链**：在最终发布提交上运行 `npm run test:all`、依赖审计和打包态冒烟并保留 CI 结果，避免后续改动使旧证据失效。
2. **持续保持干净环境验证**：CI 在全新依赖安装后执行单元/契约测试、依赖审计、源码态 Electron 冒烟、截图工具栏交互、macOS 目录包构建和打包态冒烟；后续发布不得跳过任一环节。
3. **真实 Mac 核心验收**：单/多显示器与 Retina 截图、精确尺寸/比例、TCC 权限拒绝与恢复、全部标注、贴图变换/分组/公式、9 语 OCR、代表性条码、所有图片格式、历史多页 PDF，以及录屏三种格式、四种音频组合、辅助功能事件、摄像头和成片画笔。
4. **继续验证安装身份的功能连续性**：`v0.3.0` 固定本机签名构建、安装、重启和 Designated Requirement 比对已完成；仍须实际执行截图与录屏，确认现有 TCC 授权在功能层面可用。不得用 CI 的 ad-hoc 产物冒充日常更新证据。
5. **长截图最低可用门槛**：至少在普通网页、横向表格、长文档和一个具有固定区域的页面验证暂停/继续、首中尾删段、撤销/重做、固定区域重拼及失败后继续；不能静默拼错。
6. **AI/隐私实测**：用测试凭据和代理或服务端日志确认请求只发往配置端点，视觉任务与本地 OCR 后文本任务的数据范围和 README 一致。
7. **使用文档与发布状态一致**：明确早期预览、macOS-only、复杂长截图限制、单图 PDF 与历史多页 PDF 的区别、AI 联网边界及所有需真机确认项；GitHub 上传后再核对匿名 clone、CI、Release 和校验和。

### P1：补齐高频体验差距

1. 把智能 UI 父子层级选择、1 px 调整、精确宽高和比例统一成更可发现的键盘/界面提示，并补 HDR 与更多显示布局验证。
2. 标注增加智能擦除、可配置水印和拖拽自定义工具栏；不把高成本语义擦除与基础发布绑定。
3. 贴图增加任意多选子集、对齐、组级关闭/保存、变换撤销、自由角度与关注区域/滤镜；公式贴图如需可回编，再另行设计源码持久化格式。
4. 长截图继续提高动态/重复/纯色、多滚动区域和固定悬浮层可靠性。只有竞品自动滚动实测成立且用户收益明确后，再做受限自动滚动原型。
5. 扩充窗口标题、进程、UUID 等文件名变量和自动保存规则；验证多页 PDF 的页面尺寸、色彩和大文件体验。
6. 录屏补 WebP 输出、进程异常恢复和需要时的中段时间线编辑；继续收紧事件捕获隐私与辅助权限提示。
7. 历史搜索增加可选 OCR 全文或标签，但需先解决索引体积、隐私开关和重建策略。

### P2：验证需求后再做，不应本轮硬追

1. Windows 正式支持；Linux 不是 PixPin 当前正式支持平台，不因“跨平台”口号盲目加入。
2. PixPin 测试版的自由形状/多区域/多窗口截图、动态 GIF/WebP 贴图与 MP4 GPU 编码。
3. 通用 JavaScript 脚本系统、全局鼠标映射；必须先设计权限、数据访问和错误隔离。
4. Typst/AsciiMath、完整 TeX/宏包生态，以及更广泛的条码格式和 OCR 语言；先用真实用户样本验证投入收益。
5. 云同步、账户、团队协作和商业付费体系；这些不在当前 PRD 的短期目标内。
