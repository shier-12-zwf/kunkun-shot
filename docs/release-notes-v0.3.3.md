# 困困截图工具 v0.3.3 发布说明

> 记录日期：2026-09-05
> 定位：贴图显示热修复，macOS 本地签名预览包

本版针对截图贴图仍显示白色文件卡片、纸张图标和“点击打开 · Cmd+C 复制路径”，却不显示截图的问题。它不增加新功能，不改变剪贴板类型识别、贴图消息内容或工作区数据格式。

## 根因与修复范围

贴图页面预先包含图片、文字、颜色和文件内容层，未使用的层带有 HTML `hidden` 属性。但是 `.pin-file`、`.pin-color` 的 `display:flex` 和 `.pin-img` 的 `display:block` 会覆盖浏览器对 `hidden` 的默认隐藏样式。图片即使成功解码，未启用的文件卡片仍可能显示在它上方；隐藏图片也可能干扰其他类型贴图的布局。

本轮已在真实 Electron 中复现：文件卡片的 `hidden` 为 `true`，实际计算样式仍为 `display:flex`。这解释了为什么图片工具栏正常、文件名为空，却出现文件卡片提示；它并不证明主进程把截图识别成了文件。

生产代码改动仅为贴图页面新增统一的 `[hidden] { display: none !important; }` 规则，确保未启用的内容层真正退出显示和布局。原有图片解码、剪贴板识别和工作区恢复链路保持不变。

## 为什么此前的测试没有拦住

此前的贴图冒烟测试主要检查图片的 `complete`、`naturalWidth`、`naturalHeight` 和地址，并确认工具栏存在。它只能证明图片已解码，不能证明图片没有被其他内容层遮住。v0.3.2 的解码和重载相关改动并未修复这次发现的 CSS 隐藏冲突；不能将旧测试通过视为本问题已解决。

本轮补充真实 Electron 显示回归：

- 图片、文字、颜色、文件四种模式分别检查初次打开和页面重新载入，共 8 个场景。
- 验证当前类型内容实际可见，其他类型内容层的计算样式为隐藏，不仅检查 DOM 属性或图片尺寸。
- 图片场景使用黑白双色样本，通过 `capturePage` 检查实际窗口像素，防止“图片解码成功但被遮住”再次漏检；黑白样本降低显示器 ICC 色彩转换对精确颜色断言的干扰。

这些探针的最终通过状态以下方本轮验证记录为准；测试设计说明不等于已完成发布验收。

## 更新与使用

通过上述门禁并发布 DMG 后：

1. 从菜单栏菜单正常退出旧版应用，避免旧进程继续显示旧页面样式。
2. 保留旧应用备份，再用本版 DMG 内的“困困截图工具.app”更新“应用程序”中的安装；无需清空设置、历史或贴图工作区。
3. 启动新版，重新截图并点击工具栏“贴图”，确认显示的是所选截图，而不是空文件卡片。
4. 如常使用 `⌘ ⇧ P` 贴出剪贴板图片、文字、颜色或 Finder 文件。正常文件贴图仍会显示文件信息，并保留打开和复制路径能力。

完整功能与流程见 [使用指南](使用指南.md)，相关故障区分见其中第 18.9 节。原始截图因屏幕权限或 DRM 而出现黑色画面、图片资源本身损坏、鼠标穿透等问题不属于本次 CSS 遮挡修复。
